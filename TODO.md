# Project roadmap

Keep this checklist focused on public, device-agnostic work. Do not add private device identifiers, personal profile exports, local paths, or credentials.

## M18 behavior and VSD Craft compatibility

- [ ] Complete behavioral parity for all VSD Craft actions usable from the M18; do not count catalog visibility or preserved settings alone as parity. Exclude K1 Pro-only and encoder/knob-only actions, and exclude boot-screen replacement per user request.
- [x] Compare the active two-page M18 profile with VSD Craft: the fork exposes all 15 LCD positions and all three physical bottom buttons on each page; the imported profile includes system controls, shortcuts, app actions, and page navigation.
- [x] Group native M18 actions into clear categories and make search cover localized labels, tooltips, identifiers, and category names; matching groups open automatically. Rust tests (23/23), search tests (3/3), and frontend checks pass. The optimized macOS app compiled; clearing inherited File Provider/provenance metadata from the generated bundle allowed strict ad-hoc signature verification (notarization is not configured). The rebuilt app was not launched; visual smoke testing remains.
- [x] Add all 103 keypad-compatible VSD Craft action definitions to the searchable M18 core catalog and import catalogued single actions using their source UUID/settings rather than converting them to inactive placeholders. The inspector exposes retained settings. This is catalog/import coverage only—not proof of runtime parity.
- [x] Add native, importable M18 actions for Siri, volume up/down, mute, Dispatch Center, Screenshot, Launchpad, Desktop Saver, display sleep/brightness, and music transport. Unsupported VSD actions are retained as explicitly labeled, inactive placeholders—not disguised as generic commands—and their original names, UUIDs, settings, artwork, and titles are preserved for later ports.
- [x] Replace the old unsupported-action `Run Command: true` fallback with an import-only native inactive placeholder. The action inspector and import summary now state that it will not execute; a Rust regression test checks identity, settings, artwork/title preservation, and native no-op routing.
- [x] Cross-check installed VSD Craft plugin manifests against the parity inventory: all 88 unique action UUIDs in the installed bundled plugin manifests are represented in the 123-UUID inventory. Reviewed Operation Flow semantics against MiraBox's guide: Multi Action runs sequentially, Carousel advances one item per press, and Action Toggle changes the active state. M18 has no knob, so Action Wheel/Action Trigger knob variants are out of scope.
- [x] Add native M18 page-number behavior: Page Indicator maps from VSD Craft and renders the current page; Go to Page imports VSD's one-based target, preserves its “Show page number” option (default true), and renders the page number over the source artwork. The M18 inspector exposes the visibility toggle. Rust tests cover VSD target conversion/import and rendered image dimensions; physical-device visual matching remains open.
- [ ] Preserve VSD composite actions during import. OpenDeck Toggle Action is behaviorally close to VSD Action Cycle, but the importer currently neither maps the VSD parent action nor reconstructs its child sequence. Do not map it by UUID/name alone until child serialization is validated against a sanitized fixture. Action Carousel dynamic artwork/state remains unverified. MiraBox documents Create Folder as a nestable one-page container, but the importer maps its UUID to profile switching and does not prove that folder contents/back-navigation survive; decide on native M18 folder-stack support or a validated flattening strategy.
- [ ] Complete action behavior and action-specific inspectors, with exact status recorded per family in `docs/VSD-CRAFT-PARITY.md`. Known gaps include VSD composite child serialization/execution, native folder-stack behavior, Super Hotkey's hardware path, Soundboard output/modes, and time/weather/YouTube/memo/interactive extras. Do not count a catalog entry or generic settings editor as parity.
- [ ] Smoke-test the updated catalog/search in the rebuilt app. The running private-worktree bundle is older and exposes one combined M18 action group, not the four new categories. Do not count it as verification of updated categories/search.
- [ ] Verify on hardware: computer-wide inactivity starts the screensaver; the first M18 press wakes it without activating the assigned action.
- [ ] Verify video and photo screensavers cover the full display, preserve LED state, and loop or advance reliably.
- [ ] Verify occupied-slot drag/drop swaps complete actions, states, settings, and artwork; empty-slot drop remains a move.
- [ ] Verify Go to Page and Page Indicator artwork, target numbering, and visibility toggle on the M18; the VSD Craft UI has the “Show page number” checkbox, while its false-value serialization remains unverified.
- [ ] Preserve the distinction between ordinary Hotkey and Super Hotkey, including switch variants and imported shortcut semantics.
- [x] Boot-screen replacement intentionally excluded per user request; do not implement or send logo-upload commands.
- [ ] Continue VSD Craft feature audit and port remaining useful action families as native M18 actions. All VSD action entries are application-core entries; do not add the M18 as an OpenDeck device plugin or add VSD action plugins as a dependency.
- [ ] Capture and archive screenshots of relevant VSD Craft action inspectors for durable evidence. This is not a blocker for parity work: the inline captures/live inspection already support comparison of visible controls, labels, defaults, and layout; use manifests, sanitized fixtures, and safe behavioral tests for semantics. Do not commit personal profile exports or device identifiers.
