# Project roadmap

Keep this checklist focused on public, device-agnostic work. Do not add private device identifiers, personal profile exports, local paths, or credentials.

## M18 behavior and VSD Craft compatibility

- [ ] Complete behavioral parity for every VSD Craft feature that applies to the M18; do not count catalog visibility or preserved settings alone as parity. The sole intentionally omitted M18 feature is boot-logo replacement. K1 Pro- and knob/encoder-only actions are not M18 features.
- [x] Compare the active two-page M18 profile with VSD Craft: the fork exposes all 15 LCD positions and all three physical bottom buttons on each page; the imported profile includes system controls, shortcuts, app actions, and page navigation.
- [x] Group native M18 actions into clear categories and make search cover localized labels, tooltips, identifiers, and category names; matching groups open automatically. Rust tests (23/23), search tests (3/3), and frontend checks pass. The optimized macOS app compiled; clearing inherited File Provider/provenance metadata from the generated bundle allowed strict ad-hoc signature verification (notarization is not configured). The rebuilt app was not launched; visual smoke testing remains.
- [x] Cover all 109 VSD Craft manifest action UUIDs applicable to the M18 in the app's core catalog/import layer: 106 single-action entries plus native Multi Action, Action Carousel, and Action Cycle parent actions; exclude six K1 Pro-only actions, seven knob-only actions, and the SecondaryScreen-only Text action. Import catalogued single-action settings and composite children natively. This is catalog/import coverage—not proof of vendor-semantic parity.
- [x] Add native, importable M18 actions for Siri, volume up/down, mute, Dispatch Center, Screenshot, Launchpad, Desktop Saver, display sleep/brightness, and music transport. Unsupported VSD actions are retained as explicitly labeled, inactive placeholders—not disguised as generic commands—and their original names, UUIDs, settings, artwork, and titles are preserved for later ports.
- [x] Replace invalid shorthand Enigo preset-key strings with typed key tokens, route supported preset shortcuts through the native input executor, and parse-test every static sequence. This verifies token validity, not that every shortcut matches VSD Craft's exact macOS behavior.
- [x] Replace the old unsupported-action `Run Command: true` fallback with an import-only native inactive placeholder. The action inspector and import summary now state that it will not execute; a Rust regression test checks identity, settings, artwork/title preservation, and native no-op routing.
- [x] Cross-check installed VSD Craft plugin manifests against the parity inventory: 123 unique action UUIDs total; 109 action behaviors apply to the M18 keypad, excluding six K1 Pro-only actions, seven knob-only actions, and one SecondaryScreen-only action. Reviewed Operation Flow semantics against MiraBox's guide: Multi Action runs sequentially, Carousel advances one item per press, and Action Toggle changes the active state. M18 has no knob or secondary screen.
- [x] Close the keypad catalog inventory gap by adding native core entries for M18 Brightness, Mouse event, Scene Shift, Microphone, Multimedia, Hotkey, and Super Hotkeys. Their remaining semantic/runtime parity is tracked by family in `docs/VSD-CRAFT-PARITY.md`.
- [x] Re-check the installed VSD Craft time-action manifests and align World Time, Timer, and Countdown default setting keys/types to the vendor schema; add regression tests.
- [x] Add dedicated M18 inspectors for text/password, open/close/website, UDP, soundboard, and the retained time/online settings. Password input is visually obscured. These inspectors are configuration coverage only where the runtime is still incomplete.
- [x] Add native soundboard output-device selection, per-action volume, Play/Stop, Play/Overlap, Play/Replay, Loop/Stop, and No fade/Fade in/Fade out/Fade in-out playback. The macOS player uses Rodio/Symphonia, exposes current output devices, and fades to configured volume over the VSD duration; format/device-switch/fade behavior still needs manual comparison on hardware. MiraBox documents per-action output routing and supported file types; encrypted M4P and exact fade edge behavior remain unverified.
- [x] Implement all seven VSD Multimedia selector choices: previous, play/pause, next, stop, mute, volume up, and volume down. Media and volume keys use the native system input path; macOS Stop currently targets Music only if Music is already running, so generic-player Stop parity remains open.
- [x] Align the M18 Brightness inspector with VSD Craft's two key actions (Increase/Decrease), track consecutive relative changes per device, and mirror the change to the app's brightness slider. Action order is based on the vendor's displayed order; exact step amount and VSD's non-zero minimum still need manual comparison. The global slider currently permits zero, so this family is not yet at parity.
- [x] Replace the Microphone action's Sound-settings shortcut on macOS with a Core Audio toggle for the current default input device's mute property. SDK selector/address logic is unit-tested; do not count as fully verified until tested on the user's actual input hardware and compared with VSD Craft.
- [x] Add native M18 page-number behavior: Page Indicator maps from VSD Craft and renders the current page; Go to Page imports VSD's one-based target, preserves its “Show page number” option (default true), and renders the page number over the source artwork. The M18 inspector exposes the visibility toggle. Rust tests cover VSD target conversion/import and rendered image dimensions; physical-device visual matching remains open.
- [x] Add a “Capture current pointer position” control for M18 mouse move/drag, expose absolute/relative coordinate mode, and make drag execution honor the saved mode. This fills the editing/runtime gap; exact VSD coordinate conventions and macOS Accessibility behavior still require manual comparison.
- [x] Move VSD Create Folder and Go back from the Starter Pack profile-switch action to native M18 folder navigation. Import resolves the vendor folder target to an imported page, and a persisted LIFO history supports nested open/back. Synthetic tests cover target resolution and stack order; imported nested-profile behavior still needs live comparison.
- [x] Import VSD composite `MultiActionData` flat and nested child actions into native M18/OpenDeck parents and execute them through application core, including explicit Delay actions, preserved `MultiActionDelays`, `Action Cycle`'s `Settings.Index`, and child artwork/state. Synthetic tests cover import normalization and identity; `Delay1`/`Delay2` meaning and Carousel/Cycle semantics still need comparison with a sanitized VSD profile and live VSD Craft.
- [x] Add hierarchical action context paths, recursive profile lookup/lifecycle handling, nested composite creation/removal, and nested flow editing. Rust tests cover context/disk round trips and recursive mutation; this is code-tested behavior, not hardware parity.
- [ ] Complete action behavior and action-specific inspectors, with exact status recorded per family in `docs/VSD-CRAFT-PARITY.md`. Known gaps include real-fixture validation of composite serialization/delays/artwork, live nested-folder target validation, Super Hotkey's physical-HID path, exact Soundboard codec/fade edge behavior, exact Mouse Event coordinate/wheel/drag semantics, and DateTime/World Time/Timer/Countdown/Calendar/Weather/YouTube/Memo/interactive extras. Do not count a catalog entry or retained settings as parity.
- [x] Verify current source checks on 2026-09-28: Rust tests pass (69 passed, 2 intentionally ignored), the targeted M18 page/HID suite passes (7/7), frontend action-search tests pass (5/5), Svelte check reports 0 errors/0 warnings, Rust formatting plus `git diff --check` pass, and the production frontend plus macOS arm64 Tauri app/DMG builds complete with their existing Svelte compatibility, large-chunk, and no-notarization warnings. The page-turn pipeline is code-tested: inactive-page warming is immediate and parallel, cached images are awaited before the atomic commit, and the HID/page-tab-to-flush timing path is instrumented. Hierarchical composite contexts and nested-flow lookup/import/editor paths are also code-tested. These checks do not establish visual or latency parity on the physical M18.
- [ ] Launch the newly built app and visually verify the current catalog groups/search, action inspectors, and device editor. A successful frontend build/search test is not visual or hardware verification.
- [ ] Verify on hardware: the M18 screen stays on while the Mac is in use regardless of M18 activity, turns off after the configured Mac idle time (and while locked, when enabled), wakes on Mac input, and the first M18 press after sleep only wakes it.
- [ ] Verify on hardware: page turns appear in a single update with no late partial/flickering images; the LED color and brightness from Settings apply (and brightness 0 turns the LEDs off), pages with an LED Colors key override the color, and the LEDs go dark while the M18 sleeps. The code-level transaction and timing instrumentation are in place, but no post-fix physical M18 page-turn run is recorded yet.
- [x] Remove the device screensaver: the M18 is an LCD panel with no burn-in risk; display sleep now follows the computer's state instead.
- [ ] Verify occupied-slot drag/drop swaps complete actions, states, settings, and artwork; empty-slot drop remains a move.
- [ ] Verify Go to Page and Page Indicator artwork, target numbering, and visibility toggle on the M18; the VSD Craft UI has the “Show page number” checkbox, while its false-value serialization remains unverified.
- [ ] Preserve the distinction between ordinary Hotkey and Super Hotkey, including switch variants and imported shortcut semantics.
- [x] Boot-screen replacement intentionally excluded per user request; do not implement or send logo-upload commands.
- [ ] Continue VSD Craft feature audit and port remaining useful action families as native M18 actions. All VSD action entries are application-core entries; do not add the M18 as an OpenDeck device plugin or add VSD action plugins as a dependency.
- [ ] Capture and archive screenshots of relevant VSD Craft action inspectors for durable evidence. This is not a blocker for parity work: the inline captures/live inspection already support comparison of visible controls, labels, defaults, and layout; use manifests, sanitized fixtures, and safe behavioral tests for semantics. Do not commit personal profile exports or device identifiers.
